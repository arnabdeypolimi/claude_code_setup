## 4. Loss Functions (Detailed)

### Stage 1: VQ Autoencoder Loss

**Reconstruction (motion space + vertex space, lip-weighted):**
```
L_recon = ||M̂ − M||₁ + w_lips ||V̂_lips − V_lips||₂ + ||V̂ − V||₂
```
- M̂/M = predicted/GT motion params (T, 106)
- V̂/V = predicted/GT FLAME vertices (T, 5023, 3)
- V̂_lips/V_lips = lip vertices only (T, 254, 3)
- w_lips = lip weight (exact value not published)

**Velocity (temporal smoothness in vertex space):**
```
L_vel = ||(V̂_{1:} − V̂_{:-1}) − (V_{1:} − V_{:-1})||₂
```

**Acceleration (anti-jitter):**
```
L_smooth = ||V̂_{2:} − 2V̂_{1:-1} + V̂_{:-2}||₂
```

**Codebook commitment loss:**
```
L_cb = ||z − sg(q)||² + β·||sg(z) − q||²
```
Where sg() = stop-gradient, z = encoder output, q = nearest codebook entry.

**Combined:**
```
L_VQ = L_recon + λ_vel·L_vel + λ_smooth·L_smooth + L_cb
```
(Exact values of λ_vel, λ_smooth, w_lips, β not published.)

### Stage 2: AR Model Loss (Cross-Entropy)

```
L_AR = −∑_T ∑_{l=1}^L log p(z_T^(l)(gt) | z_T^(<l)(gt), z_{T−1}^(L)(gt), a_T, s)
```
- Teacher forcing: uses ground-truth codes as both input and target
- z_T^(l)(gt) = ground-truth code at window T, scale l

## 6. Ablation Studies (Full Tables)

### Table 5: Main Ablation on TFHP Dataset

| Variant | LVE ↓ | FDD ↓ | MOD ↓ | What was removed / changed |
|---------|-------|-------|-------|---------------------------|
| w/o Multi-Scale AR | 14.14 | 22.04 | 3.06 | Removed multi-scale hierarchy entirely |
| w/o Style Embedding | 11.80 | 21.46 | 2.37 | Removed speaker style conditioning |
| Clip 8, Layer 5 | 11.73 | 24.89 | 2.25 | Window=8f, scales=[1,2,4,8] |
| Clip 25, Layer 5 | 10.20 | 19.00 | 1.97 | Window=25f, scales=[1,5,10,15,25] |
| w/o Temporal VQ | 9.82 | 18.60 | 1.86 | Standard multi-scale VAE (no causal cross-window) |
| w/o Temporal AR | 9.97 | 18.71 | 1.99 | Single-window AR (no cross-window conditioning) |
| Clip 50, Layer 5 | 9.78 | 18.03 | 1.89 | Window=50f, scales=[1,5,10,25,50] |
| **ARTalk (Full)** | **9.34** | **18.15** | **1.81** | Window=100f, scales=[1,5,25,50,100] |

**Findings:**
1. Removing multi-scale AR is catastrophic (+4.80 LVE) — most critical component
2. Style embedding removal is second-most impactful (+2.46 LVE)
3. Longer windows consistently improve all metrics
4. Temporal VQ and temporal AR each contribute independently

| 25 | 5 | [1, 5, 10, 15, 25] | 10.20 | 19.00 | 1.97 |
| 50 | 5 | [1, 5, 10, 25, 50] | 9.78 | 18.03 | 1.89 |
| 100 | 3 | [1, 50, 100] | 11.03 | 20.82 | 2.01 |

## 9. Evaluation Metrics (Exact Definitions)

### LVE — Lip Vertex Error
- **Definition:** Maximum L2 error of lip vertices per frame
- **Formula:** max over 254 lip vertices of ||V̂_lip − V_lip||₂ per frame, averaged over dataset
- **Vertex region:** FLAME "lips" mask = 254 vertices (from FLAME_masks.pkl)
- **Measures:** Temporal precision of lip synchronization
- **Source:** Follows CodeTalker (Xing et al. 2023)
- **Lower = better**

### FDD — Upper Face Dynamic Deviation
- **Definition:** Standard deviation of upper facial motion (predicted vs GT)
- **Formula:** std(||V̂_upper_trajectory − V_upper_trajectory||) over time
- **Vertex region:** FLAME "eye_region" + "forehead" masks = 884 vertices
- **Measures:** Expressiveness and consistency of non-lip facial motion (head movement style)
- **Source:** Follows CodeTalker (Xing et al. 2023)
- **Lower = better**

### MOD — Mouth Opening Distance (also called MMD)
- **Definition:** Average difference in mouth opening region between predictions and GT
- **Formula:** avg ||mouth_opening_predicted − mouth_opening_gt||
- **Measures:** Stylistic similarity of mouth opening (less temporally sensitive than LVE)
- **vs LVE:** MOD ≈ style of mouth; LVE ≈ precise sync timing
- **Source:** Similar to DiffPoseTalk (Sun et al. 2024)
- **Lower = better**

**Important:** The paper explicitly notes that existing works rarely specify exact vertex selections for these regions. FLAME official masks are used here for reproducibility.

## 12. Paper vs Code Discrepancies

These are confirmed differences between what the paper describes and what the codebase implements. Knowing these avoids confusion when reading both.

### Motion Dimension: D=56 (paper) vs D=106 (code)

**Paper (Section 3.1 and supplementary Section 7):**
- Expression ψ: **50-dim**
- Pose θ: **6-dim** (head rotation + jaw combined)
- Motion vector D = **56**
- Shape β: described as 100-dim for EMICA annotation

**Code (`core/constants.py`, `core/types.py`):**
- Expression: **100-dim** (`EXPRESSION_DIM = 100`)
- Head rotation: **3-dim** (`MotionParams.head_rotation`)
- Jaw: **3-dim** (`MotionParams.jaw`)
- Motion vector D = **106** (`MOTION_DIM = 106`)
- Shape β: **300-dim** (`FLAME_SHAPE_DIM = 300`)

**Why the difference:** The paper describes the configuration used in the TFHP dataset annotations (EMICA outputs 50-dim expression). The code implements the full FLAME configuration (100-dim expression blendshapes, standard 300-dim shape). The codebase is the authoritative implementation — the paper describes a simplified view of the data.

### Codebook: Standard VQ (paper) vs BSQ (code)

**Paper:** Describes 256-entry standard Vector Quantization codebook with 64-dim codes.

**Code (`motion/vae/quantizer.py`):** Implements Binary Spherical Quantization (BSQ) with `V_CODE_DIM=32` bits → implicit 2^32 codebook. BSQ avoids codebook collapse without explicit codebook entries.

The paper's conceptual description (VQ) and the code's implementation (BSQ) achieve the same purpose but through different mechanisms.

## 14. Limitations

**Limitation 1 — Prosody-driven head movement only:**
Head movements are driven by speech prosody (rhythm, stress, intonation), not semantic content. No meaningful gestures: no nodding for affirmation, no head-shaking for negation. These require semantic understanding beyond the AR model.

**Limitation 2 — Single style embedding per utterance:**
A single 128-dim style embedding per utterance cannot capture dramatic within-utterance emotional shifts. A calm→excited transition in the middle of a sentence cannot be smoothly represented.

**Future directions noted by authors:**
1. Incorporate semantic information into head motion generation
2. More flexible (dynamic) style control (e.g., time-varying style)
3. Handle dramatic emotional transitions within utterances
